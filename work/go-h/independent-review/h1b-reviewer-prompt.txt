LAYER A (eligibility scope). Question class: option-dependent source-level branch activation. In scope: changes to an option's semantics (declaration, default, type, apply, readOnly, path) traceable to an option-dependent branch predicate; changes to a boolean predicate that directly or indirectly consumes option state and controls selection, emission, enabling, rejection or branch choice. Out of scope: documentation-only changes; configuration-value assignments config.<path> = ...; changes to message text when the condition is unchanged; shell or external-command tests (including inside derivation strings); test-only changes (test files are not Layer-A consumers); import-list registration; package-only changes. Layer A claims only the selection decision, never downstream runtime behavior.

CATEGORIES. E_DIRECT: changed term reads only options declared in the same module. E_INDIRECT: changed term reads an option declared in another module, or reaches option state through a let binding or helper declared in another module. E_AMBIGUOUS: not decidable by the procedure. E_NO: out of scope, or traceability established absent, or EC10 equivalence established at level EQ0-EQ2.

PREDICATE ROLES. Question for a boolean: does it control whether a source-level element, path, value, definition or branch is selected, emitted, enabled, rejected or taken?
  P_GATING: decides whether a definition, list element, attribute, module fragment or assertion is active (lib.mkIf cond, lib.optional(s) cond, conditional items in lib.mkMerge, assertion and warning conditions, cond && x in definition position).
  P_CONTROL: chooses which alternative expression is evaluated (if-then-else in value position, guard forms).
  P_SELECTION: is the predicate of a function that keeps or drops elements of a list or attrset (lib.filter, lib.filterAttrs, builtins.filter, lib.partition, lib.findFirst, lib.remove, or any function whose role is keeping or dropping elements by a boolean; the list is not closed, role decides).
  P_DATA_ONLY: value is only converted to output data and selects nothing.
  P_UNKNOWN: role cannot be classified from the source at the stated commit.
Eligible roles: P_GATING, P_CONTROL, P_SELECTION. A predicate change is E-eligible iff its role is eligible and its operands read option state (directly, through an exact alias, through a let binding, or through a lambda parameter). P_DATA_ONLY or a shell/external-command test is E_NO. P_UNKNOWN with option operands is E_AMBIGUOUS.

LAMBDA RULE. A lambda passed as the predicate argument of a P_SELECTION function is a predicate. A lambda whose result is a value (map, mapAttrs, concatMap, concatMapAttrs, transforms) is not a predicate merely because it mentions an option. A predicate lambda is eligible iff its boolean controls selection and its outcome depends on option state, directly or through a lambda parameter iterating an option-derived collection (traced through let bindings). A predicate passed by name is classified by resolving that name's binding in the same file at the same commit; if unresolvable, P_UNKNOWN. A predicate whose boolean depends only on static values is E_NO. If the iterated collection cannot be traced to a named option path, E_AMBIGUOUS.

LET-BINDING RULE. A let binding is transparent: a binding that is a pure expression of named option paths carries the option state of those paths; the category is set by declaration_module_governs of the traced paths, not by the binding site. An exact alias (cfg = config.x) is a direct read of x. A helper function declared in another module makes reads through it E_INDIRECT.

EC10 EQUIVALENCE LEVELS (for a rewritten expression, base vs head). EQ0: textual identity after normalizing location, whitespace and line breaks. EQ1: identical AST after dropping formatting, comments and redundant parentheses. EQ2: bounded local normalization of exactly three kinds: (a) alpha-renaming of lambda parameters and let bindings without capture; (b) attribute-path sugar with identical AST meaning; (c) commensurate path spelling where a same-file let alias binds exactly the option path. EQ3: any equivalence needing semantic reasoning (global bindings or imports, dynamic attribute names, non-local computation, operand or list reordering, any other normalization). EC10_AUTOMATIC is true for EQ0-EQ2 and false for EQ3. Forbidden as automatic normalizations: reordering operands of && or ||; reducing !(!x) to x; reordering list elements; adding or removing mkDefault/mkForce/mkOverride wrappers; replacing an expression by a literal with the same current value without evaluating the source; any equivalence needing a binding outside the same expression.
